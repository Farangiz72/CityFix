# 10. Тестирование / Testing

Rule: **every requirement needs at least one test case.** The seven cases from the presentation
cover only five of the seven requirements — **FR-5 and NFR-1 remained unchecked**, therefore
**TC-8** and **TC-9** were added.

## 10.1 Виды проверок / Four types of checks (slide 19)

| Вид / Type | Что проверяем | Как |
| --- | --- | --- |
| Функциональная / Functional | каждый сценарий от начала до результата | пройти путь целиком в интерфейсе |
| Права доступа / Access rights | роль не может чужое действие | вызов API под каждой из четырёх ролей |
| Данные и файлы / Data and files | валидация полей, тип и размер файла | граничные значения, «плохие» файлы |
| Устройства / Devices | вёрстка и работа на телефоне и ноутбуке, разные браузеры | ручная проверка на 2 устройствах × 2 браузерах |

## 10.3 Обработка ошибок / Error handling

```
найдена  →  описана и передана  →  исправлена  →  перепроверена
            (шаги воспроизведения,
             ожидаемый и фактический результат)
```

- Пока перепроверка не выполнена, ошибка считается **открытой** (`open`).
- Список ошибок ведётся в GitHub Issues с тегом `bug` (допущение / assumption).
- Формат описания: окружение, шаги, ожидаемо, фактически, скриншот/лог, требование и TC-x.

## 10.6 Прогон волны 1 / Wave 1 executed run (16.11.2026)

Стенд тот же: `prisma db push` → `npm run seed` (1006 заявок, 6 пользователей) → API на `:4000`.
Скрипт: `backend/scripts/smoke-wave1.ps1` (ASCII, PowerShell 5.1); запуск —
`powershell -ExecutionPolicy Bypass -File .\scripts\smoke-wave1.ps1`.
