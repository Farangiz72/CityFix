# 12. Готовность, риски, допущения / Readiness, risks, assumptions

## 12.1 Критерии готовности к защите / Readiness criteria

| # | Критерий | Как проверяется | Статус |
| --- | --- | --- | --- |
| 1 | `docker compose up` поднимает систему с нуля на чистом компьютере | чистая машина, `git clone` → `cp .env.example .env` → `up --build` | ✔ |
| 2 | Весь путь «Новая → Проверена → В процессе → Выполнена» проходит через интерфейс под тремя ролями | демо: житель → оператор → исполнитель | ✔ |
| 3 | Карта, форма и загрузка фото работают, интерфейс удобен на телефоне | проверка на телефоне и ноутбуке | ✔ |
| 4 | Права четырёх ролей защищены на сервере (TC-4 пройден) | `PATCH` под токеном жителя → `403` | ✔ |
| 5 | Все тест-кейсы выполнены, открытых ошибок нет | [06-test-cases.md](06-test-cases.md), раздел с отчётом | ✔ |
| 6 | В `docs/` есть требования, UML, ER, макеты и тест-кейсы | этот каталог | ✔ |
| 7 | Слайды сверены с реальным проектом, вместо `[Фамилия Имя]` — имена, добавлены группа и преподаватель | ручная правка презентации | ⏳ |

## 12.2 Риски / Risks

| Риск | Проявление | Меры / Mitigation |
| --- | --- | --- |
| **Не хватит времени на всё** | часть функций к защите не готова | идти по MoSCoW: сначала сквозной сценарий от создания до «Выполнена», FR-5 — в последнюю очередь |
| **Фронтенд ждёт бэкенд** | простой второй половины команды | контракт API фиксируется в спринте 1 ([09-api-contract.md](09-api-contract.md)); до готовности сервера интерфейс работает на заглушках |
| **Конфликты в Git** | потерянные правки, «сломанный» `develop` | короткие ветки, Pull Request каждый день, один владелец на папку, ревью обязательное |
| **Дыры в правах** | житель может сделать действие оператора | роль проверяется только на сервере (`requireRole`); TC-4 и проверка «чужих» заявок выполняются в каждом спринте |
| **Слайды расходятся с реальностью** | на защите показывают одно, в системе другое | в заметках докладчика несколько раз сказано «подогнать пункты под реальную работу»; после реализации сверить слайды 8, 11, 18 и 20 |
| **Потеря фото при перезапуске** | ссылки в БД есть, файлов нет | фото лежат в docker volume `uploads`, а не в контейнере; `down -v` — осознанный сброс |
| **Секреты в репозитории** | утечка `JWT_SECRET` | только `.env.example`, реальный `.env` в `.gitignore`; compose отказывается стартовать без `JWT_SECRET` |

## 12.3 Допущения и открытые вопросы / Assumptions and open questions

The presentation has no such slide — the team has to settle these in sprint 1. Current decisions:

| # | Вопрос | Решение (допущение) | Последствие |
| --- | --- | --- | --- |
| 1 | Язык сервера, СУБД и хранение фото не названы | Node.js + Express + TypeScript, SQLite (файл в проекте), диск (volume) | при другой стеке (Java, C#, Python, PostgreSQL) схема данных и API остаются те же |
| 2 | Длительность спринта не указана | 1–2 недели | блоки на схеме не масштабированы по времени |
| 3 | Кто именно меняет какой статус — не сказано | своя версия в [07-roles-and-statuses.md](07-roles-and-statuses.md) | матрица переходов зафиксирована на сервере |
| 4 | В цикле нет статуса «Отклонена» (замечание в заметках) | добавлен переход `NEW → REJECTED` с обязательной причиной | житель видит причину отказа, цикл замкнут |
| 5 | Права администратора на просмотр заявок не указаны | видит всё, статус не меняет | маршруты админа — только чтение |
| 6 | `main` обновляется после демо | да, в конце каждого спринта | на защите показывается `main` |
| 7 | Список ошибок ведётся в GitHub Issues с тегом `bug` | да | трассировка «ошибка → исправление → перепроверка» |
| 8 | Регистрация открыта всем | регистрация даёт роль `RESIDENT`; остальные роли — из начальных данных | на демо роли уже созданы |
| 9 | Миграции vs `db push` | для учебного стенда `prisma db push` при старте; `prisma migrate dev` — когда появится первая постоянная БД | при смене схемы данные пересоздаются, для курса приемлемо |
| 10 | Нужен ли отдельный сервер БД | нет: SQLite-файл `backend/data/cityfix.db` (в Docker — volume `db_data`) | запуск одной командой без установки СУБД; при росте нагрузки — переход на PostgreSQL сменой `provider` и возвратом `enum` |
| 11 | Нужен ли интернет для адреса | да, начиная с BL-T6: подсказки идут через прокси к Photon/Nominatim | без сети работают ручная точка на карте и ввод адреса текстом; геокодер никогда не вызывается с клиента, ключ — только в `.env` |

  и условия использования фиксируются в [10-backlog.md](10-backlog.md) §13.4.1;
- единые дизайн-токены (`tokens.css`) с берёзовой палитрой.
